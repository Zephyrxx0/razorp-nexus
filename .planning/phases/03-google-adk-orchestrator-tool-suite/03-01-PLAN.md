<threat_model>
ASVS Level: 1
Block on: high severity threats

- Threat T-03-01: Malformed, adversarial, or out-of-bounds intent strings (e.g., negative quantities, quantities > 100, prompt injection payloads) causing unhandled runtime errors, database arithmetic overflow, or resource exhaustion.
  - ASVS Control: V5.1.1 (Input Validation - boundary verification, schema coercion, and rejection of out-of-bounds quantities).
  - Mitigation: `parse_intent` strictly enforces integer quantity range [1, 100], defaulting missing quantities to 1, and immediately raises `IntentValidationError` on <= 0 or > 100 before any downstream steps execute.

- Threat T-03-02: Payment credential leak or tampering in offline/mock testing environments.
  - ASVS Control: V3.1.1 (Cryptographic Key Management - environment isolation for mock mode, non-leakage of live test secrets).
  - Mitigation: Dual-mode `RazorpayClientAdapter` activates `MockRazorpayClient` whenever `NEXUS_RAZORPAY_MOCK=true` or when mock keys are used, generating deterministic synthetic `pay_test_<hex>` payment IDs and test orders in-memory without sending cleartext keys over the wire.
</threat_model>

<action>

2. Create `nexus_agent/tools/intent.py` implementing Decision D-01:
   - Define Pydantic schema `ParsedIntentResponse(product_query: str, quantity: int = 1, buyer_email: str, confidence: float = 1.0)`.
   - Regex fallback patterns:
     - `BUY_PATTERN = re.compile(r"^(?:buy|purchase|order|get|need)\s+(?:(\d+)\s+)?(.+?)(?:\s+for\s+([\w\.-]+@[\w\.-]+\.\w+))?$", re.IGNORECASE)`
     - `FALLBACK_PATTERN = re.compile(r"^(?:(\d+)\s+)?(.+?)(?:\s+for\s+([\w\.-]+@[\w\.-]+\.\w+))?$", re.IGNORECASE)`
   - Implement `_parse_intent_regex(intent_string: str, fallback_email: str) -> dict`:
     - Matches regex patterns, extracts quantity (defaults to 1 if None), product query, and email.
     - Normalizes email via `normalize_email()`.
     - Validates quantity: if `quantity <= 0` or `quantity > 100`: raises `IntentValidationError(f"Invalid quantity {quantity}. Must be between 1 and 100.")`.
   - Implement `_parse_intent_gemini(intent_string: str, buyer_email: str) -> dict`:
     - Calls `gemini-2.0-flash` with structured output schema `ParsedIntentResponse` via `google.genai` or `google.generativeai`.
     - System prompt instructs model to extract target product name, numeric quantity (default 1), and buyer email.
   - Implement public function `async def parse_intent(intent_string: str, buyer_email: str = "", merchant_id: str = "", google_api_key: str = "") -> dict`:
     - If `google_api_key` is non-empty and `not os.environ.get("NEXUS_OFFLINE_TEST")`: attempts `_parse_intent_gemini()`. On any exception or fallback, falls back to `_parse_intent_regex()`.
     - Validates quantity bounds: `<= 0` or `> 100` raises `IntentValidationError`.
     - Normalizes email and returns dict:
       `{"product_query": product_query, "quantity": quantity, "buyer_email": buyer_email, "confidence": confidence}`.
3. Create `nexus-agent/tests/test_intent.py`:
   - `test_parse_intent_regex_standard_patterns`: test `"Buy 2 Nitro Cold Brew"`, `"Purchase 1 Quantum Keyboard"`, `"Order Nexus Router"`. Verify default quantity is 1 and queries are cleaned.
   - `test_parse_intent_bounds_rejection`: test quantity 0, negative (-5), and > 100 (101, 500) raise `IntentValidationError`.
   - `test_parse_intent_email_normalization`: test `"BUY 1 item FOR Buyer@Example.COM  "` normalizes email to `"buyer@example.com"`.
   - `test_parse_intent_gemini_fallback`: mock Gemini failure and assert regex parser takes over seamlessly.
   - `test_parse_intent_latency_budget`: assert execution of regex parser completes in < 5ms.
</action>
