<threat_model>
ASVS Level: 1
Block on: high severity threats

- Threat T-03-03: Concurrency race condition or negative stock overselling when multiple agents attempt concurrent purchases against depleted inventory.
  - ASVS Control: V11.1.4 (Concurrency Controls - atomic database transactions and conditional row updates).
  - Mitigation: `resolve_catalog` executes single-statement conditional SQL update (`UPDATE products SET stock = stock - $1 WHERE id = $2 AND stock >= $1 RETURNING stock`), raising `StockError` immediately if 0 rows are returned.

- Threat T-03-04: Bypassing trust evaluation or LLM hallucination calling payment APIs for high-risk or known-fraud buyers (trust score < 40).
  - ASVS Control: V4.1.1 (Access Control - programmatic defense-in-depth enforcement independent of LLM decisions).
  - Mitigation: `create_razorpay_order` unconditionally inspects `trust_score` and raises `TrustViolationError` if `trust_score < 40`, blocking any call to the Razorpay SDK or mock client.

- Threat T-03-05: Denial-of-service or unhandled network failure when connecting to the Trust Graph microservice on port 8001.
  - ASVS Control: V14.2.1 (Resilience & Fail-safe Defaults - graceful degradation under service disruption).
  - Mitigation: `check_trust_graph` enforces a strict 500ms timeout with `httpx.AsyncClient` and soft-fails to score 50.0 (`decision="REVIEW"`, `risk_factors=["trust_service_unavailable"]`), avoiding crashes while preventing unearned `ALLOW` privileges.
</threat_model>

<action>
1. Create `nexus_agent/tools/catalog.py` implementing Decision D-02:
   - Implement `async def resolve_catalog(merchant_id: str, product_query: str, quantity: int, pool: asyncpg.Pool) -> dict`:
     - Validate `quantity >= 1`.
     - Query `products` table for `merchant_id`:
       `SELECT id, name, price_paise, stock FROM products WHERE merchant_id = $1 AND (name ILIKE $2 OR description ILIKE $2) LIMIT 1` (with `$2 = f"%{product_query}%"`).
     - If no record found: raise `ProductNotFoundError(f"No product matching '{product_query}' found for merchant {merchant_id}.")`.
     - Execute atomic conditional decrement directly in SQL:
       ```sql
       UPDATE products
       SET stock = stock - $1, updated_at = clock_timestamp()
       WHERE id = $2 AND merchant_id = $3 AND stock >= $1
       RETURNING id, name, price_paise, stock + $1 AS stock_before, stock AS stock_after;
       ```
     - If returning row is None (insufficient stock):
       - Query current stock: `SELECT stock FROM products WHERE id = $1 AND merchant_id = $2`.
       - Raise `StockError(f"Insufficient stock for product '{name}'. Requested {quantity}, available {stock}.")`.
     - Compute `total_amount_paise = price_paise * quantity`.
     - Return dict:
       `{"product_id": str(row["id"]), "name": row["name"], "price_per_unit_paise": row["price_paise"], "total_amount_paise": total_amount_paise, "quantity": quantity, "stock_before": row["stock_before"], "stock_after": row["stock_after"]}`.
   - Implement `async def rollback_catalog_stock(product_id: str, quantity: int, pool: asyncpg.Pool) -> int`:
     - Compensatory increment rollback for failed downstream transactions:
       ```sql
       UPDATE products
       SET stock = stock + $1, updated_at = clock_timestamp()
       WHERE id = $2
       RETURNING stock;
       ```
     - Returns new restored stock integer.
2. Create `nexus-agent/tests/test_catalog.py`:
   - `test_resolve_catalog_exact_match_decrements_stock`: assert stock decrements atomically and returned dict matches schema.
   - `test_resolve_catalog_insufficient_stock_raises_stock_error`: set available stock < requested quantity, assert `StockError` is raised.
   - `test_resolve_catalog_unknown_product_raises_not_found`: assert unknown product name raises `ProductNotFoundError`.
   - `test_compensatory_rollback_restores_inventory`: simulate stock decrement followed by `rollback_catalog_stock`, assert stock count is restored to original value.
</action>
