<threat_model>
ASVS Level: 1
Block on: high severity threats

- Threat T-06-01: Unauthorized access or credential leakage in MaaS client tool invocations.
  - ASVS Control: V3.1.1 (Cryptographic Key Management), V13.1.1 (Generic Web Service Security).
  - Mitigation: `query_merchant_catalog` and `transact_with_merchant` inject `Authorization: Bearer <token>` in HTTP headers. Tokens are never logged in plaintext or written to disk. Requests sanitize buyer inputs.
- Threat T-06-02: Unhandled network timeout or model failure halting buyer agent during live stage demonstration.
  - ASVS Control: V14.4.1 (Resilience & Error Handling).
  - Mitigation: Dual-mode LLM execution (D-02): If `GEMINI_API_KEY` / `GOOGLE_API_KEY` is not present, or if an API exception occurs, `DemoBuyerAgent` seamlessly falls back to a deterministic semantic/heuristic parser without crashing or leaking sensitive stack traces.
</threat_model>

### Task 1: MaaS Client Tools Implementation (06-01-01)
<files>
nexus-agent/nexus_agent/tools/maas_client.py

nexus-agent/tests/test_demo_buyer.py

<action>
1. Create `nexus-agent/nexus_agent/tools/maas_client.py` providing typed async functions wrapped for Google ADK `FunctionTool` consumption (per D-03):
   - `query_merchant_catalog(merchant_id: str, query: str = "", max_price_paise: int | None = None, in_stock: bool = True, base_url: str = "http://localhost:3000", token: str = "") -> dict`:
     - Dispatches HTTP `GET {base_url}/api/maas/{merchant_id}/catalog?q={query}&in_stock={in_stock}` using `httpx.AsyncClient(timeout=10.0)`.
     - Sets header `Authorization: Bearer {token}` when `token` is provided.
     - Parses response JSON. Returns dict with status `"SUCCESS"`, `products` list (each containing `id`, `name`, `description`, `price_paise`, `stock`, `agent_purchase_url`), and count.
     - Handles HTTP 401 (invalid token), 404 (merchant not found), and connection errors gracefully returning `{"status": "ERROR", "error_code": "...", "message": "..."}`.
   - `transact_with_merchant(merchant_id: str, intent: str, buyer_email: str, ip: str = "127.0.0.1", device_id: str = "nexus_buyer_device_01", user_agent: str = "NexusDemoBuyer/1.0", upi_handle: str | None = None, base_url: str = "http://localhost:3000", token: str = "") -> dict`:
     - Dispatches HTTP `POST {base_url}/api/maas/{merchant_id}/transact` with JSON payload:
       ```json
       {
         "intent": intent,
         "buyer": {
           "email": buyer_email,
           "ip": ip,
           "device_id": device_id,
           "user_agent": user_agent,
           "upi_handle": upi_handle
         }
       }
       ```
     - Sets header `Authorization: Bearer {token}`.
     - Handles HTTP 200 (SUCCESS with `transaction_id`, `razorpay_order_id`, `razorpay_payment_id`, `status`, `audit_trail`).
     - Handles HTTP 403 (DENIED with `trust_score`, `trust_decision`, `risk_factors`, `audit_trail`).
     - Handles HTTP 409 (INSUFFICIENT_STOCK), 422 (INTENT_PARSE_FAILED), 500/502 (FAILED).
     - Returns parsed structured outcome dict.
2. Export `query_merchant_catalog` and `transact_with_merchant` in `nexus-agent/nexus_agent/tools/__init__.py`.
3. Create test suite in `nexus-agent/tests/test_demo_buyer.py` testing:
   - `test_query_merchant_catalog_success`: mock HTTP 200 returning catalog items with bearer auth header check.
   - `test_query_merchant_catalog_auth_failure`: mock HTTP 401 returning error dict.
   - `test_transact_with_merchant_success`: mock HTTP 200 returning payment captured receipt.
   - `test_transact_with_merchant_denied`: mock HTTP 403 returning trust denial and risk factors.
</action>

### Task 2: Autonomous Demo Buyer Agent Runtime & CLI (06-01-02)
<files>

<action>
1. Create `nexus-agent/nexus_agent/agents/demo_buyer.py`:
   - Define Google ADK `demo_buyer = Agent(...)` per PRD §9.2:
     - `name="DemoBuyerAgent"`
     - `model="gemini-2.0-flash-exp"`
     - `description="Simulates an AI buyer agent that shops via the Nexus MaaS API."`
     - `instruction=BUYER_INSTRUCTION`
     - `tools=[FunctionTool(query_merchant_catalog), FunctionTool(transact_with_merchant)]`
   - Define typed execution receipt model:
     ```python
     class BuyerExecutionReceipt(BaseModel):
         success: bool
         merchant_id: str
         goal: str
         selected_product: dict[str, Any] | None = None
         transaction_id: str | None = None
         razorpay_order_id: str | None = None
         razorpay_payment_id: str | None = None
         amount_paise: int | None = None
         amount_inr: str | None = None
         status: str
         trust_score: float | None = None
         audit_steps_count: int = 0
         timeline: list[str] = []
         error_message: str | None = None
     ```
   - Implement `class DemoBuyerAgent`:
     - Constructor: `def __init__(self, merchant_id: str, token: str, base_url: str = "http://localhost:3000", buyer_email: str = "demo-buyer@nexus.ai", ip: str = "103.21.44.132", device_id: str = "nexus_buyer_device_01", user_agent: str = "NexusDemoBuyer/1.0 google-adk/0.1", model: str = "gemini-2.0-flash-exp", api_key: str | None = None, verbose: bool = True)`
     - Method `async def run(self, goal: str) -> BuyerExecutionReceipt`:
       - Emits structured telemetry via `rich.console.Console` (or clean ANSI fallback):
         - `[1/4] DISCOVER`: Query catalog with semantic keyword extraction from `goal`.
         - `[2/4] EVALUATE`: Filter items by in-stock status and optimization criteria (e.g., "cheapest" -> sort by `price_paise ASC`; "best" -> match score).
         - `[3/4] TRANSACT`: Send `transact_with_merchant` call with structured buyer fingerprint.
         - `[4/4] VERIFY`: Validate payment capture details, Razorpay ID, and audit steps.
       - **Dual-Mode LLM Logic (D-02):**
         - Checks if `GEMINI_API_KEY` or `GOOGLE_API_KEY` or constructor `api_key` is available and `os.environ.get("NEXUS_OFFLINE_TEST") != "1"`.
         - If available: attempts live Google ADK runner / tool calling with Gemini.
         - If unavailable or on exception: executes deterministic heuristic shopping parser:
           1. Parses `goal` (extracts keywords like "headphones", "shoes", "shirt", extracts constraints like "cheapest" or "under X").
           2. Calls `query_merchant_catalog`.
           3. Evaluates returned items and picks best match.
           4. Calls `transact_with_merchant` with formatted intent `"Buy 1 unit of {product['name']}"`.
           5. Parses response and builds `BuyerExecutionReceipt`.
   - Implement CLI entrypoint (`if __name__ == "__main__":` and `main()` function):
     - Uses `argparse`:
       - `--merchant`: Merchant UUID or short ID (required or reads from env `DEMO_MERCHANT_ID`)
       - `--token`: MaaS Bearer token (required or reads from env `DEMO_MAAS_TOKEN`)
       - `--goal`: Shopping goal string (default: `"Buy the cheapest wireless headphones"`)
       - `--base-url`: Next.js MaaS base URL (default: `http://localhost:3000`)
       - `--json`: Output receipt as JSON
     - Formats rich presentation banner, execution steps, and final colored receipt card.
2. Export `DemoBuyerAgent`, `demo_buyer`, and `BuyerExecutionReceipt` in `nexus-agent/nexus_agent/agents/__init__.py`.
3. Add unit and integration tests in `nexus-agent/tests/test_demo_buyer.py`:
   - `test_demo_buyer_heuristic_cheapest`: tests agent run selecting the cheapest item when multiple items returned.
   - `test_demo_buyer_heuristic_denied`: tests agent handling of 403 DENIED response.
   - `test_demo_buyer_cli_args`: tests CLI argument parser with defaults and custom flags.
   - `test_demo_buyer_receipt_serialization`: tests Pydantic model serialization to JSON.
</action>
