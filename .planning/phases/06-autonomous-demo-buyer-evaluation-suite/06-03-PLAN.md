### Task 1: Multi-Merchant Ring Attack Simulator (06-03-01)
<files>
scripts/simulate_ring_attack.py
nexus-agent/tests/test_simulate_ring_attack.py
</files>
<action>
1. Create `scripts/simulate_ring_attack.py` (per D-11):
   - Enforce CLI options via `argparse`:
     - `--target`: Target service, choices `["maas", "trust-service"]` (default: `maas`).
     - `--ring-size`: Number of syndicate identities (default: `12`).
     - `--transactions`: Total attack transactions to dispatch (default: `50`).
     - `--pace-ms`: Delay between transactions in milliseconds (default: `300`).
     - `--auto-seed`: Auto-seed test merchants if missing (default: `True`).
     - `--base-url`: Next.js MaaS base URL (default: `http://localhost:3000`).
     - `--trust-url`: FastAPI Trust Graph URL (default: `http://localhost:8001`).
   - Topology & Merchant Setup (D-09, D-12):
     - Auto-detects $\ge 3$ merchants (e.g. Apex Electronics, Zenith Apparel, Urban Threads). If fewer than 3 exist in the DB, seeds standard test merchants with known Bearer tokens (`maas_live_*`).
     - Generates 12 synthetic fraudsters (`attacker_01@darkweb.org` .. `attacker_12@darkweb.org`).
     - Coordinated shared attributes: 3 unique hardware device IDs (`dev_syndicate_a1`, `dev_syndicate_a2`, `dev_syndicate_a3`), 2 shared `/24` subnets (`198.51.100.0/24`, `203.0.113.0/24`), and shared UPI handles.
   - Attack Sequence & Progression (D-10):
     - Dispatches 50 transactions distributed across the 3+ merchants.
     - Early transactions (tx 2-4) include a deliberate payment failure or risk signal to ensure community detection Criterion 4 (`failed_transaction_count >= 1`) is met.
     - Shows an active terminal progress bar and logs each transaction with status and trust score:
       - Txs 1–5: Clean probing, scores $\approx 85.0$.
       - Txs 6–14: Shared device clustering, score degrades $85 \rightarrow 50$.
       - Tx 15+: 2-hop local ego ring detector triggers, member nodes marked `is_known_fraud=True`, scores collapse to $0.0$.
       - Txs 16–50: All transactions rejected with HTTP 403 Forbidden (`status: DENIED`, `trust_score: 0`).
     - Respects `--pace-ms` delay (200-500ms) to allow live visual graph clustering in the merchant dashboard Cytoscape UI.
   - Summarizes final attack metrics: Total sent, Total blocked, First detection at transaction #, Legitimate users affected (0).
2. Create unit and simulation tests in `nexus-agent/tests/test_simulate_ring_attack.py`:
   - `test_syndicate_topology_generation`: asserts 12 identities, shared devices, shared subnets.
   - `test_in_memory_ring_attack_progression`: runs the attack logic against an in-memory `GraphManager` and `TrustScorer`, asserting that trust score collapses from initial high score down to 0.0, and transactions past threshold are classified as DENY.
</action>

### Task 2: 3-Act End-to-End Demo Script & Cryptographic Audit Inspection (06-03-02)
<files>
scripts/demo_e2e.py
nexus-agent/tests/test_demo_e2e.py
</files>
<action>
1. Create `scripts/demo_e2e.py`:
   - Command-line arguments:
     - `--auto`: Non-interactive mode (skips presenter `Press [Enter]` pauses, essential for CI).
     - `--base-url`: Next.js base URL (default: `http://localhost:3000`).
     - `--trust-url`: Trust Graph URL (default: `http://localhost:8001`).
     - `--db-url`: PostgreSQL URL (default: `postgresql://nexus:nexus@localhost:5432/nexus`).
   - **Pre-Flight Health Checks (D-16):**
     - Checks PostgreSQL connectivity (port 5432).
     - Checks Next.js health endpoint (`http://localhost:3000/api/health` or `GET /`).
     - Checks FastAPI Trust Graph health endpoint (`http://localhost:8001/health`).
     - Prints clear status indicators: `[OK] PostgreSQL`, `[OK] Next.js`, `[OK] Trust Graph Engine`. If any service is offline, prints actionable startup command and exits cleanly.
   - **Act 1 — Merchant Onboarding & Catalog Verification (D-13):**
     - Verifies active test merchant (`Apex Electronics`) and verifies catalog items exist with integer paise pricing.
     - Confirms valid MaaS Bearer token.
     - Pauses for presenter commentary unless `--auto`.
   - **Act 2 — Autonomous AI Buyer Transacts (ALLOW Path) (D-13, D-14, D-15):**
     - Instantiates `DemoBuyerAgent` with goal `"Buy the cheapest wireless headphones from Apex Electronics"`.
     - Executes purchase through MaaS API.
     - **Proof Display (D-14):** Logs formatted proof card:
       - Nexus Transaction ID (`UUID`)
       - Razorpay Order ID (`order_*`)
       - Razorpay Payment ID (`pay_*`)
       - Captured Status: `captured`
       - Amount: Formatted ₹ and integer paise (e.g. `₹4,999.00 [499900 paise]`)
       - Trust Score: $\ge 80.0$ (Decision: `ALLOW`)
     - **Cryptographic Hash Chain Verification (D-15):**
       - Traverses audit trail returned in response (or queries `GET /api/audit/{tx_id}`).
       - Verifies SHA-256 parent link integrity: `current_entry.parent_hash == sha256(previous_entry)`.
       - Renders ASCII timeline table of all 6 steps with step latencies and rationale.
       - Prints `"SEALED INTEGRITY: VALID"` badge.
     - Pauses for presenter commentary unless `--auto`.
   - **Act 3 — Fraud Ring Attack & Real-Time Contagion Interception (D-13, D-15):**
     - Executes coordinated ring attack against merchant using `simulate_ring_attack.py` logic.
     - Demonstrates live trust score collapse ($85 \rightarrow 50 \rightarrow 10 \rightarrow 0$).
     - Sends final syndicate transaction and logs HTTP 403 response:
       - Confirms `status: "DENIED"`, `trust_score: 0.0`.
       - Confirms `razorpay_order_id: null` (Zero payment movement).
       - Confirms reserved catalog inventory was preserved / rolled back.
     - Verifies DENY audit chain: Step 1 (Parse Intent) $\rightarrow$ Step 2 (Resolve Catalog) $\rightarrow$ Step 3 (Check Trust Graph - DENIED) $\rightarrow$ Compensatory Rollback $\rightarrow$ Step 6 (Log Audit Entry).
     - Renders DENY ASCII timeline and `"SEALED INTEGRITY: VALID"` badge.
     - Displays summary defense metrics: 0 legitimate buyers blocked, ₹0 False-Positive Cost for ring attack.
2. Create unit and integration tests in `nexus-agent/tests/test_demo_e2e.py`:
   - `test_preflight_checks`: tests health check parser with mock services.
   - `test_audit_hash_chain_validation`: tests parent hash linking on mock 6-step audit records, verifying that intact chains pass and tampered chains raise an integrity error.
   - `test_demo_e2e_auto_flow`: executes `demo_e2e.py` with mock network handlers in non-interactive `--auto` mode, asserting exit code 0.
</action>
