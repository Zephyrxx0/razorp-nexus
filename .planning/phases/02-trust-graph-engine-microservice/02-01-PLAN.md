<threat_model>
ASVS Level: 1
Block on: high severity threats

- Threat T-02-01: Malformed or unescaped signal keys injected during graph ingestion causing cross-entity node collisions or memory corruption.
  - ASVS Control: V5.1.1 (Input Validation - sanitization of signal keys and strict prefix isolation).
  - Mitigation: `GraphManager.get_node_key()` strips any redundant `sha256:` prefix and strictly formats keys as `{signal_type}:{signal_val}`, isolating email, ip, device, upi, and user-agent namespaces.

- Threat T-02-02: Race conditions and internal dictionary mutation collisions during concurrent scoring and feedback ingestion.
  - ASVS Control: V11.1.4 (Concurrency & Race Conditions - lock isolation prevents dictionary corruption and race-condition exploitation during scoring).
  - Mitigation: `AsyncRWLock` grants concurrent shared read access to multiple scoring requests (`POST /trust/score`) while requiring an exclusive write lock for graph modifications (`POST /trust/signal`), guaranteeing thread-safe NetworkX graph access.
</threat_model>

<action>
1. Create `trust-graph-service/app/core/__init__.py`.
2. Create `trust-graph-service/app/core/lock.py` implementing `AsyncRWLock` citing decision D-09:
   - Maintain internal counters `_readers` (int), `_writer` (bool), an `asyncio.Lock()`, and two condition variables `_read_ready` and `_write_ready`.
   - Implement `@asynccontextmanager async def read()`: acquire the internal lock, wait on `_read_ready` while `_writer` is active, increment `_readers`, yield for concurrent read execution, and in finally decrement `_readers` and notify `_write_ready` if `_readers == 0`.
   - Implement `@asynccontextmanager async def write()`: acquire the internal lock, wait on `_write_ready` while `_writer` is true or `_readers > 0`, set `_writer = True`, yield for exclusive graph modification, and in finally reset `_writer = False` and notify both `_write_ready` and all waiting `_read_ready`.
3. Create `trust-graph-service/tests/test_graph_manager.py` with test case `test_async_rw_lock_concurrency()`:
   - Verify that multiple concurrent coroutines can enter `async with lock.read()` simultaneously without blocking each other.
   - Verify that when a coroutine enters `async with lock.write()`, all subsequent read and write acquisitions block until the writer releases the lock.
   - Verify that reader release cleanly wakes waiting writers, and writer release cleanly wakes waiting readers.
</action>

1. Create `trust-graph-service/app/engine/__init__.py`.
2. Create `trust-graph-service/app/engine/graph_manager.py` implementing `GraphManager`:
   - Initialize `self.graph = nx.Graph()` and an `AsyncRWLock` instance `self.lock = AsyncRWLock()`.
   - Implement `get_node_key(signal_type: str, signal_val: str) -> str`: strip any `sha256:` prefix, strip whitespace, and return `{signal_type}:{val}` conforming to D-03.
   - Implement `extract_node_keys(fingerprint: dict[str, Any]) -> list[str]`: parse `email_hash` (type "email"), `ip_subnet` (type "ip"), `device_hash` (type "device"), `upi_handle` (type "upi"), and `user_agent_hash` (type "ua"), returning the list of non-empty formatted node keys.
   - Implement `ingest_signal(fingerprint: dict[str, Any], merchant_id: str, transaction_id: str, outcome: str, amount_paise: int, timestamp: datetime | None = None) -> tuple[int, int]`:
     - Determine failure boolean (`outcome in ("DENIED", "FAILED")`).
     - For each extracted node key, add node if not present with attributes: `signal_type`, `signal_value`, `is_known_fraud=False`, `trust_score=100.0`, `ring_id=None`, `merchant_ids_seen={merchant_id}`, `transaction_count=1`, `failed_transaction_count=(1 if failure else 0)`, `successful_transaction_count=(0 if failure else 1)`, `first_seen=ts`, `last_seen=ts`, and `transactions` list containing the initial transaction record.
     - If node already exists, update attributes: add `merchant_id` to `merchant_ids_seen`, increment `transaction_count`, increment `failed_transaction_count` or `successful_transaction_count`, update `last_seen = max(last_seen, ts)`, and append the transaction record to `transactions` list.
     - Generate an undirected clique among all extracted node keys: for every unique pair of nodes `(u, v)`, if edge exists increment `weight += 1.0`, add `merchant_id` to `merchants_shared` set, and update `last_seen`; if edge does not exist create edge with `weight=1.0`, `edge_type="SHARED_TRANSACTION"`, `merchants_shared={merchant_id}`, `first_seen=ts`, and `last_seen=ts`.
     - Return tuple of `(nodes_updated, edges_updated)`. Adhere strictly to D-04 by mutating only the in-memory graph without initiating PostgreSQL writes.
3. In `trust-graph-service/tests/test_graph_manager.py`, add comprehensive unit tests:
   - `test_node_key_formatting_and_prefix_stripping`: assert `email:sha256:abc` normalizes to `email:abc` and `ip:103.21.44` yields `ip:103.21.44`.
   - `test_ingest_signal_clique_creation`: ingest a 5-signal fingerprint, assert 5 nodes created, assert 10 edges created (5 nodes pair count), and assert each edge has weight 1.0 and contains the merchant ID.
   - `test_ingest_signal_repeat_increments_weight`: ingest identical fingerprint a second time under a different merchant, assert node transaction counts equal 2, edge weights equal 2.0, and `merchant_ids_seen` contains both merchants.
   - `test_ingest_signal_tracks_failures`: ingest transaction with outcome `FAILED`, verify `failed_transaction_count` increments to 1 while `successful_transaction_count` remains 0.
</action>
