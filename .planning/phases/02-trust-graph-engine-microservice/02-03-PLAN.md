<threat_model>
ASVS Level: 1
Block on: high severity threats

- Threat T-02-07: Service startup crash loops or denial of service when PostgreSQL is slow or temporarily unreachable during system boot.
  - ASVS Control: V1.14.1 (Resilience & Availability - soft-start and fail-safe handling without unhandled crash loops).
  - Mitigation: Citing D-02, `rehydrate_from_db()` catches database connection failures, logs a soft-start warning, boots the FastAPI HTTP server on port 8001 with an empty graph, and spawns a background asyncio retry loop that polls every 5 seconds until the database becomes healthy.

- Threat T-02-08: Cross-merchant PII leakage or active offensive scanning violating defense-only boundaries.
  - ASVS Control: V1.4.1 (Defense-Only Operations - strictly passive observation and bounded graph queries without offensive reconnaissance or remote code execution).
  - Mitigation: Citing RING-04, the service never initiates external HTTP queries or network scans; all node identities are SHA-256 hashes or /24 subnet truncations. Citing D-15, `GET /trust/graph` enforces a hard limit of 200 nodes and supports optional `merchant_id` scoping to prevent data dumping and guarantee 60fps rendering in Cytoscape.js.
</threat_model>

### Task 1: PostgreSQL Rolling 30-Day Rehydration & Soft-Start Background Retry Loop

- 02-PATTERNS.md (§3.7 Rehydration adaptation)
- db/py/nexus_db/client.py

<action>
1. Create `trust-graph-service/app/engine/rehydration.py` implementing database restoration:
   - Implement `async def rehydrate_from_db(graph_manager: Any, db_pool: Any, days: int = 30) -> int`:
     - Citing D-01, acquire a connection from `db_pool` and query `transactions` where `created_at >= NOW() - INTERVAL '30 days'` ordered by `created_at ASC`.
     - Select columns: `id`, `merchant_id`, `buyer_fingerprint`, `amount_paise`, `status`, `created_at`.
     - Acquire exclusive `graph_manager.lock.write()`.
     - For each transaction row, parse `buyer_fingerprint` JSONB and ingest via `graph_manager.ingest_signal()`, passing transaction timestamp to recreate true temporal state.
     - After all rows are ingested, run `detect_all_rings(graph_manager.graph)` to classify historical clusters (such as seed Cluster A and Cluster B).
     - Return count of rehydrated transactions.
   - Implement `async def soft_start_rehydration_loop(graph_manager: Any, get_pool_func: Any, retry_interval: float = 5.0) -> None`:
     - Citing D-02, wrap initial DB connection and rehydration in a try/except catching `asyncpg.PostgresError`, `OSError`, and `ConnectionRefusedError`.
     - If connection fails on boot, log warning `"PostgreSQL not available at startup. Booting with empty graph (soft-start mode)."` and enter a background loop sleeping `retry_interval` seconds until `get_pool_func()` succeeds and `rehydrate_from_db` completes.
2. Create `trust-graph-service/tests/test_rehydration.py`:
   - `test_rehydration_from_mock_pool`: mock asyncpg pool returning historical transactions matching seed data, verify nodes, edges, and ring detection are properly initialized.
   - `test_soft_start_handles_connection_refused`: pass a failing pool connection function, verify `soft_start_rehydration_loop` does not raise an unhandled exception and retries until success.
   - `test_rehydration_respects_30_day_window`: verify transactions older than 30 days are omitted by the SQL query filter.
</action>

1. Create `trust-graph-service/app/config.py` using `pydantic_settings.BaseSettings`:
   - Define `Settings`: `port: int = 8001`, `database_url: str = "postgres://postgres:postgres@localhost:5432/nexus"`, `rehydrate_days: int = 30`, `periodic_sweep_interval_sec: int = 300`. Configure `env_prefix = ""`.
2. Create `trust-graph-service/app/core/scheduler.py`:
   - Implement `async def periodic_ring_detection_sweep(graph_manager: Any, interval_seconds: int = 300)`: loop sleeping for `interval_seconds`, acquire `graph_manager.lock.write()`, execute `detect_all_rings(graph_manager.graph)`, and update `graph_manager.rings`.
3. Create `trust-graph-service/app/api/__init__.py`.
4. Create `trust-graph-service/app/api/routes_health.py`:
   - Endpoint `GET /health`: return JSON with `status: "healthy"`, `nodes_count`, `edges_count`, and `rings_count`.
   - Endpoint `GET /`: return service metadata (`service: "nexus-trust-graph-service"`, `version: "0.1.0"`).
5. Create `trust-graph-service/app/api/routes_trust.py`:
   - Endpoint `POST /trust/score`: parse `ScoreRequest`, acquire `graph_manager.lock.read()`, call `TrustScorer.score_fingerprint()`, and return `ScoreResponse`.
   - Endpoint `POST /trust/signal`: parse `SignalRequest`, acquire `graph_manager.lock.write()`, call `graph_manager.ingest_signal()`, and return `SignalResponse`.
   - Endpoint `GET /trust/rings`: acquire `graph_manager.lock.read()`, return list of `RingDetailResponse` dicts from `graph_manager.rings.values()`.
   - Endpoint `GET /trust/node/{node_id}`: acquire `graph_manager.lock.read()`, if `node_id` not in graph raise 404, else return `NodeDetailResponse`.
   - Endpoint `GET /trust/graph`: query parameters `merchant_id: UUID | None = None` and `limit: int = 200`. Acquire `graph_manager.lock.read()`, call `graph_manager.get_merchant_subgraph(str(merchant_id) if merchant_id else None, min(limit, 200))`, and return Cytoscape graph payload.
6. Create `trust-graph-service/app/main.py`:
   - Define async `lifespan(app: FastAPI)` context manager:
     - Initialize `GraphManager` on `app.state.graph_manager`.
     - Attempt DB pool initialization via `nexus_db.client.get_db_pool()`.
     - Spawn background task `soft_start_rehydration_loop()` to populate graph without blocking startup.
     - Spawn background task `periodic_ring_detection_sweep()` for 5-minute sweeps.
     - Yield to run application.
     - On shutdown, cancel background tasks and close database pool.
   - Instantiate `app = FastAPI(title="Nexus Trust Graph Microservice", version="0.1.0", lifespan=lifespan)`.
   - Add CORS middleware allowing all origins (`*`) for Next.js dashboard local development.
   - Include routers `routes_health.router` and `routes_trust.router`.
7. Create `trust-graph-service/tests/test_api.py` with FastAPI `TestClient` integration tests:
   - `test_health_endpoint`: verify GET /health returns 200 and healthy status.
   - `test_post_trust_score_allow`: submit clean fingerprint, verify 200 status, decision `ALLOW`, score >= 70, breakdown present.
   - `test_post_trust_score_deny`: submit known fraud fingerprint, verify 200 status, decision `DENY`, score < 40.
   - `test_post_trust_signal_ingestion`: submit transaction outcome, verify 200 status and `status: "INGESTED"`.
   - `test_get_trust_rings_endpoint`: verify GET /trust/rings returns list matching `RingDetailResponse` schema.
   - `test_get_trust_node_profile`: verify GET /trust/node/{id} returns node details and ego graph; verify non-existent node returns 404.
   - `test_get_trust_graph_merchant_filter_and_limit`: verify GET /trust/graph?limit=50 caps nodes at 50; verify merchant filter isolates relevant nodes.
