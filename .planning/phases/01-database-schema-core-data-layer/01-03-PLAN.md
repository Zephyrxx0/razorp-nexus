# Plan 01-03: Seed Catalog, Precomputed Embeddings & Rehydration Data

## Executive Summary

To enable rapid developer onboarding, continuous integration, and seamless Phase 2 Trust Graph rehydration without requiring an active Gemini API key on container boot, this plan delivers pre-seeded data across 3 diverse merchants (Apex Electronics, Urban Threads, Gourmet Direct). It populates 24 realistic SKUs with offline precomputed 768-dimensional Gemini `text-embedding-004` vectors, provides an on-demand regeneration script (`db/scripts/generate_embeddings.py`), inserts ~20 historical transactions (including a coordinated 6-transaction cross-merchant fraud ring pattern), and validates the entire schema via automated migration and end-to-end verification scripts (`db/scripts/test-schema.ts`).

---

## Locked Decisions Honored

- **D-01:** Raw SQL migration files mounted in `docker-entrypoint-initdb.d` + lightweight runner as single source of truth across Python and TypeScript.
- **D-03:** HNSW index (`vector_cosine_ops`) on `products.embedding` + B-Tree indexes on relational foreign keys.
- **D-09:** Pre-computed offline embeddings in `seeds/02_products.sql` (generated via Gemini `text-embedding-004`) + `scripts/generate_embeddings.py` for on-demand regeneration, enabling zero-delay offline boot.
- **D-10:** 3 distinct seed merchants ("Apex Electronics", "Urban Threads", "Gourmet Direct") with ~8 SKUs each across distinct verticals to support >=3 merchant fraud ring testing.
- **D-11:** Baseline historical transaction seed set (~20 transactions across 3 merchants with benign and ring fingerprints) to enable immediate schema verification and Phase 2 graph rehydration (TRUST-05).
- **D-12:** Strict PostgreSQL CHECK constraints (`CHECK (price_paise > 0)`, `CHECK (stock >= 0)`, `CHECK (currency = 'INR')`, `CHECK (amount_paise > 0)`).
- **D-13:** Standard hex string format `iv:auth_tag:ciphertext` for AES-256-GCM encrypted merchant secrets.
- **D-15:** Prefixed Bearer token format `maas_live_<hex32>` stored as `maas_token_hash` + `token_preview`.

<action>
1. Create `db/scripts/migrate.ts`:
   - Standalone migration runner that connects to PostgreSQL using `@nexus/db`.
   - Sequentially executes `db/schema.sql`, `db/seeds/01_merchants.sql`, `db/seeds/02_products.sql`, and `db/seeds/03_transactions.sql`.
   - Handles idempotency and logs execution time per file.
2. Create `db/scripts/test-schema.ts`:
   - Validates that `merchants` count == 3.
   - Validates that `products` count == 24 and all `price_paise > 0` and `stock >= 0`.
   - Executes an HNSW vector similarity search query:
     ```sql
     SELECT id, name, category, (embedding <=> $1::vector) AS distance
     FROM products
     ORDER BY distance ASC LIMIT 3;
     ```
     Asserts that nearest neighbors are returned in sub-10ms.
   - Validates that `transactions` count >= 20, checking cross-merchant ring clustering queries:
     ```sql
     SELECT buyer_fingerprint->>'email_hash' AS email_hash, count(DISTINCT merchant_id) AS merchant_count
     FROM transactions
     GROUP BY email_hash
     HAVING count(DISTINCT merchant_id) >= 2;
     ```
     Asserts that at least 2 multi-merchant fraud clusters are detected.
   - Executes `SELECT id, verify_audit_chain(id) FROM transactions` and asserts 100% of audit chains evaluate to `true`.
3. Create TypeScript trigger test script `db/scripts/test-triggers.ts` using `@nexus/db`:
   - Connects to database using `@nexus/db` client.
   - Inserts dummy merchant and transaction records.
   - Inserts audit entry step 1 with `prev_entry_hash = 'GENESIS'` and valid SHA-256 hash.
   - Asserts that executing `UPDATE audit_entries SET reason = 'tampered'` throws an error with code `23514` or `integrity_constraint_violation`.
   - Asserts that executing `DELETE FROM audit_entries WHERE id = ...` throws an error with code `23514` or `integrity_constraint_violation`.
   - Inserts step 2 with valid hash chaining, runs `SELECT verify_audit_chain($1)` and asserts `true`.
   - Cleans up dummy test records.
</action>
