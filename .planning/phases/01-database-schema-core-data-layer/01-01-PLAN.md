# Plan 01-01: Database Infrastructure & Schema DDL

## Executive Summary

This plan provisions the PostgreSQL 16 database container with the `pgvector` extension and deploys the canonical schema DDL (`db/schema.sql`). It enforces integer paise financial constraints across products and transactions, provisions the 768-dimensional HNSW cosine index for product embeddings, and implements dual defense-in-depth immutability on `audit_entries` (PL/pgSQL trigger + `nexus_app` role revocation). Finally, it implements the in-engine PL/pgSQL `verify_audit_chain(UUID)` function and verifies trigger immutability with an automated pure SQL test script (`db/scripts/test-triggers.sql`).

---

## Locked Decisions Honored

- **D-01:** Raw SQL migration files mounted in `docker-entrypoint-initdb.d` as single source of truth across Python and TypeScript.
- **D-03:** HNSW index (`vector_cosine_ops`) on `products.embedding` + B-Tree indexes on relational foreign keys (`merchant_id`), transaction status/created_at, and buyer fingerprint fields.
- **D-04:** Central `db/` repository directory containing `schema.sql`, `docker-compose.yml`, `seeds/`, and client adapters.
- **D-05:** Dual defense-in-depth: PostgreSQL `BEFORE UPDATE OR DELETE` trigger raising explicit SQL exception + `REVOKE UPDATE, DELETE` permissions on application database user role (`nexus_app`).
- **D-06:** Cryptographic SHA-256 hash-chaining on `AuditEntry` (`prev_entry_hash` and `entry_hash` per transaction).
- **D-08:** Dual verification helpers: PostgreSQL SQL function `verify_audit_chain(tx_id UUID)` + client verification libraries.
- **D-12:** Strict PostgreSQL CHECK constraints (`CHECK (price_paise > 0)`, `CHECK (stock >= 0)`, `CHECK (currency = 'INR')`, `CHECK (amount_paise > 0)`) enforced directly by the database engine.

1. `CREATE EXTENSION IF NOT EXISTS vector;` and `CREATE EXTENSION IF NOT EXISTS "uuid-ossp";` (or `pgcrypto`).
2. Table `merchants`:
   - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
   - `name VARCHAR(255) NOT NULL`
   - `email VARCHAR(255) NOT NULL UNIQUE`
   - `razorpay_key_id VARCHAR(255) NOT NULL`
   - `razorpay_key_secret TEXT NOT NULL`

   - `maas_token_hash VARCHAR(64) NOT NULL UNIQUE`
   - `token_preview VARCHAR(32) NOT NULL`
   - `maas_endpoint VARCHAR(512) NOT NULL`
   - `is_active BOOLEAN NOT NULL DEFAULT true`
   - `created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()`
   - `updated_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()`
3. Table `products`:
   - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
   - `merchant_id UUID NOT NULL REFERENCES merchants(id) ON DELETE CASCADE`
   - `name VARCHAR(255) NOT NULL`
   - `description TEXT NOT NULL`
   - `price_paise BIGINT NOT NULL CHECK (price_paise > 0)`
   - `currency VARCHAR(3) NOT NULL DEFAULT 'INR' CHECK (currency = 'INR')`
   - `stock INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0)`
   - `category VARCHAR(100) NOT NULL`
   - `tags TEXT[] NOT NULL DEFAULT '{}'`
   - `embedding vector(768) NOT NULL`
   - `is_active BOOLEAN NOT NULL DEFAULT true`
   - `created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()`
   - `updated_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()`
   - Index: `CREATE INDEX idx_products_embedding_hnsw ON products USING hnsw (embedding vector_cosine_ops);`
   - Indexes: `merchant_id`, `category`, `is_active`.
4. Table `transactions`:
   - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
   - `merchant_id UUID NOT NULL REFERENCES merchants(id) ON DELETE RESTRICT`
   - `intent_raw TEXT NOT NULL`
   - `intent_parsed JSONB NOT NULL DEFAULT '{}'::jsonb`
   - `product_id UUID REFERENCES products(id) ON DELETE SET NULL`
   - `quantity INTEGER NOT NULL CHECK (quantity > 0)`
   - `amount_paise BIGINT NOT NULL CHECK (amount_paise > 0)`
   - `currency VARCHAR(3) NOT NULL DEFAULT 'INR' CHECK (currency = 'INR')`
   - `buyer_fingerprint JSONB NOT NULL`
   - `trust_score NUMERIC(5,2)`
   - `trust_decision VARCHAR(10) CHECK (trust_decision IN ('ALLOW', 'REVIEW', 'DENY'))`
   - `trust_risk_factors TEXT[] NOT NULL DEFAULT '{}'`
   - `razorpay_order_id VARCHAR(255)`
   - `razorpay_payment_id VARCHAR(255)`
   - `status VARCHAR(20) NOT NULL DEFAULT 'PENDING' CHECK (status IN ('PENDING', 'SUCCESS', 'DENIED', 'FAILED', 'PARTIAL'))`
   - `failure_reason TEXT`
   - `created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()`
   - `resolved_at TIMESTAMPTZ`
   - Indexes: `merchant_id`, `status`, `created_at`, and GIN/Expression indexes on `((buyer_fingerprint->>'email_hash'))` and `((buyer_fingerprint->>'ip_subnet'))`.
5. Table `audit_entries`:
   - `id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
   - `transaction_id UUID NOT NULL REFERENCES transactions(id) ON DELETE CASCADE`
   - `step_name VARCHAR(50) NOT NULL`
   - `step_number INTEGER NOT NULL CHECK (step_number >= 1)`
   - `timestamp TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp()`
   - `duration_ms INTEGER NOT NULL DEFAULT 0 CHECK (duration_ms >= 0)`
   - `input_summary TEXT NOT NULL`
   - `output_summary TEXT NOT NULL`
   - `reason TEXT NOT NULL`
   - `raw_data JSONB NOT NULL DEFAULT '{}'::jsonb`
   - `is_error BOOLEAN NOT NULL DEFAULT false`
   - `prev_entry_hash VARCHAR(64) NOT NULL`
   - `entry_hash VARCHAR(64) NOT NULL`
   - `CONSTRAINT uq_audit_entries_tx_step UNIQUE (transaction_id, step_number)`
   - Index: `CREATE INDEX idx_audit_entries_tx_step ON audit_entries(transaction_id, step_number);`

### Task 3: Dual Defense-in-Depth Immutability, PL/pgSQL Verifier & Trigger Test Script
<read_first>
- `.planning/phases/01-database-schema-core-data-layer/01-CONTEXT.md` (D-05, D-06, D-08)
- `.planning/phases/01-database-schema-core-data-layer/01-RESEARCH.md` (§3 Dual Defense-in-Depth Immutability)
- `.planning/REQUIREMENTS.md` (AUDIT-01, AUDIT-02)
- `PRD.md` (§10 Data Models & Types)
</read_first>
<action>
1. Append to `db/schema.sql`:
   - PL/pgSQL trigger function `prevent_audit_mutation()` that raises `integrity_constraint_violation` ('audit_entries table is append-only: UPDATE and DELETE operations are strictly prohibited').
   - Trigger `trg_audit_entries_immutable` attached `BEFORE UPDATE OR DELETE ON audit_entries FOR EACH ROW`.
   - Application user role creation `nexus_app` with password `nexus_app_secret`.
   - Explicit permission revocations: `GRANT USAGE ON SCHEMA public TO nexus_app; GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO nexus_app; REVOKE UPDATE, DELETE, TRUNCATE ON audit_entries FROM nexus_app;`.
   - PL/pgSQL function `verify_audit_chain(p_tx_id UUID) RETURNS BOOLEAN`:
     - Checks sequential ordering starting at `step_number = 1`.
     - Checks `prev_entry_hash = 'GENESIS'` for step 1, and previous `entry_hash` thereafter.
     - Computes SHA-256 over pipe-separated preimage (`prev_entry_hash|transaction_id|step_number|step_name|input_summary|output_summary|reason|is_error`) and asserts equality with stored `entry_hash`.
     - Returns `TRUE` if all valid and `count > 0`, otherwise `FALSE`.
2. Create pure SQL test script `db/scripts/test-triggers.sql`:
   - Inserts a dummy merchant and transaction.
   - Inserts audit entry step 1 with `prev_entry_hash = 'GENESIS'` and valid SHA-256 hash.
   - Tests `UPDATE`: In a `DO $$ ... $$` PL/pgSQL block, attempts `UPDATE audit_entries SET reason = 'tampered' WHERE id = ...`. Catches exception `SQLSTATE '23514'` (or `integrity_constraint_violation`); if no exception is raised, raises `RAISE EXCEPTION 'UPDATE trigger failed: mutation was allowed'`.
   - Tests `DELETE`: In a `DO $$ ... $$` PL/pgSQL block, attempts `DELETE FROM audit_entries WHERE id = ...`. Catches exception `SQLSTATE '23514'`; if no exception is raised, raises `RAISE EXCEPTION 'DELETE trigger failed: deletion was allowed'`.
   - Inserts audit entry step 2 with valid hash chaining referencing step 1's `entry_hash`.
   - Tests `SELECT verify_audit_chain(tx_id)` and asserts result is `TRUE`.
   - Cleans up dummy test records.
</action>

</automated>
</verify>
