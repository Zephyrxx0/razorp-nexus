# Plan 01-02: Cryptographic Utilities & Cross-Language Parity Suite

## Executive Summary

Project Nexus coordinates between a TypeScript Next.js 14 MaaS gateway and Python Google ADK / FastAPI microservices. This plan establishes the cryptographic engine and shared database client adapters in both languages. It creates a unified test vector fixture (`db/fixtures/crypto-fixtures.json`), delivers `@nexus/db` (TypeScript) and `nexus_db` (Python), and implements AES-256-GCM secret encryption (`iv:auth_tag:ciphertext`), buyer signal normalization (email lowercase, IPv4 `/24` masking, User-Agent whitespace collapsing), PII sanitization for audit logs, and SHA-256 hash-chaining verification with 100% cross-language parity asserted by Vitest and Pytest.

---

## Locked Decisions Honored

- **D-02:** `pg` (node-postgres with `pg.Pool`) singleton helper with parameterized queries for TypeScript (`db/ts/src/client.ts`).
- **D-04:** Central `db/` repository directory containing shared client adapters for TS (`nexus-gateway`) and Python (`nexus-agent` & `trust-graph-service`).
- **D-06:** Cryptographic SHA-256 hash-chaining on `AuditEntry` (`prev_entry_hash` and `entry_hash` per transaction).
- **D-07:** Strict PII sanitization helper before audit write (storing only SHA-256 email/UA and /24 subnet, never plaintext secrets or raw PII) + flexible JSONB column.
- **D-08:** Dual verification helpers: PostgreSQL SQL function + shared client verification libraries in TypeScript and Python (`verifyAuditChain` / `verify_audit_chain`).
- **D-13:** Standard hex string format `iv:auth_tag:ciphertext` (12-byte IV, 16-byte auth tag, variable ciphertext in hex with colon separator) for AES-256-GCM encrypted merchant secrets.
- **D-14:** Strict shared signal normalization rules (trim, lowercased emails, IPv4 /24 subnet regex `x.y.z.0/24`, normalized User-Agent) codified in TS and Python crypto utilities with cross-language test vectors.
- **D-15:** Prefixed Bearer token format `maas_live_<hex32>` shown once to merchant at creation; stored in database strictly as `maas_token_hash` (SHA-256) + `token_preview` for display.
- **D-16:** Shared `crypto-fixtures.json` test vector suite verified by both `pytest` (Python) and `vitest` (TypeScript) testing cross-decryption and identical hashing.
