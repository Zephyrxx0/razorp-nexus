<threat_model>
ASVS Level: 1
Block on: high severity threats

- Threat T-05-04: Cross-tenant catalog manipulation allowing one merchant to update or delete another merchant's products.
  - ASVS Control: V4.1.1 (Access Control - tenant boundary).
  - Mitigation: `POST`, `PATCH`, `DELETE` operations on `/api/merchant/products` enforce `WHERE id = $1 AND merchant_id = $2`. Attempting to update or delete a product belonging to a different `merchant_id` returns 404 Not Found without modifying database rows.

- Threat T-05-05: Incomplete or broken audit trail tampering visibility.
  - ASVS Control: V7.1.1 (Audit Logging - tamper-evident integrity).
  - Mitigation: The slide-out audit drawer validates the hash chain against the stored database records before presenting the "Hash Chain Verified" shield badge. If a hash mismatch is detected, the drawer displays a high-severity tamper warning.

- Threat T-05-06: DoS and memory exhaustion via malicious CSV upload.
  - ASVS Control: V5.1.1 (Input Validation - file upload parsing).
  - Mitigation: CSV parser limits upload size to 1MB (maximum 200 products), validates all required headers (`name, description, price_inr, stock, category`), and validates integer numeric ranges before executing batched SQL inserts.
</threat_model>

1. Implement `src/app/api/merchant/products/route.ts`:
   - `GET`: Accepts `?merchant_id=UUID`. Returns array of products ordered by `created_at DESC` with `amount_paise`, stock, category, `is_ai_purchasable`, and embedding status.
   - `POST`: Accepts `{ merchant_id, name, description, price_paise, stock_quantity, category, is_ai_purchasable }` or array for CSV batch imports.
     - Enforces integer paise discipline (`price_paise >= 0`).
     - Inserts into `products` table.
     - Calls `generateProductEmbedding(description)` using Gemini `text-embedding-004` (768-dim) and updates `embedding = $1::vector`.
     - Returns created product object with 201 Created.
   - `PATCH`: Accepts `{ id, merchant_id, stock_quantity?, is_ai_purchasable?, price_paise?, name?, description? }`.
     - Updates product within tenant boundary (`WHERE id = $1 AND merchant_id = $2`).
     - If description changed, recalculates Gemini embedding.
     - Returns updated product.
   - `DELETE`: Accepts `?id=UUID&merchant_id=UUID`. Deletes product within tenant boundary.
2. Implement unit tests in `test/merchant-catalog.test.ts` validating:
   - Rejection of negative or non-integer paise amounts.
   - Tenant isolation (cannot edit another merchant's product).
   - Embedding generation sync into `products.embedding`.
</action>
