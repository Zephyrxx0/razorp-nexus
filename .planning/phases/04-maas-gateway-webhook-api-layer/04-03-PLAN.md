<objective>
Implement the production-grade Razorpay webhook ingestion endpoint (`POST /api/webhooks/razorpay`) and background graph feedback loop. The webhook handler reads the raw HTTP payload text once, computes HMAC-SHA256 using `RAZORPAY_WEBHOOK_SECRET`, and verifies the `X-Razorpay-Signature` header using length-guarded timing-safe comparison (`crypto.timingSafeEqual`). It handles `payment.captured`, `payment.failed`, and `order.paid` events, updates transaction records in PostgreSQL, and enforces strict terminal state idempotency (safely acknowledging duplicate deliveries for transactions already marked `SUCCESS` or `FAILED`). Upon valid status transitions, it dispatches non-blocking, error-isolated telemetry signals to Trust Graph port 8001 (`POST /trust/signal`) to dynamically update graph edge weights and node attributes in real time. Provide a signed webhook fixture generator helper for deterministic local and CI testing.
</objective>

<threat_model>
ASVS Level: 1
Block on: high severity threats

- Threat T-04-08: Webhook forgery and replay attacks allowing malicious actors to spoof payment success or trigger false transaction confirmations.
  - ASVS Control: V3.4.1 (Cryptographic Signatures), V13.2.1 (Data Integrity - message authenticity).
  - Mitigation: Gateway computes HMAC-SHA256 over the exact raw body text using `RAZORPAY_WEBHOOK_SECRET` and validates against `X-Razorpay-Signature` (D-13). Requests with missing, malformed, or invalid signatures are rejected immediately with 400 Bad Request before any database lookups occur.

- Threat T-04-09: Timing attacks on HMAC comparison allowing signature brute-forcing, or Denial of Service via buffer length mismatch crashes in `crypto.timingSafeEqual`.
  - ASVS Control: V3.2.1 (Timing Attack Resistance).
  - Mitigation: `timingSafeCompare` converts strings to UTF-8 buffers and executes an explicit byte length check (`bufA.length !== bufB.length ? false : crypto.timingSafeEqual(bufA, bufB)`) per §6.3. This guarantees constant-time evaluation for validly sized buffers and prevents uncaught `RangeError` runtime crashes on malformed inputs.

- Threat T-04-10: State corruption, inventory double-increment/decrement, or conflicting audit logs caused by duplicate or out-of-order webhook deliveries.
  - ASVS Control: V13.2.3 (Transaction State Consistency & Idempotency).
  - Mitigation: Gateway implements a terminal state idempotency guard checking `transactions.status` in PostgreSQL: if the transaction is already in terminal `SUCCESS` or `FAILED`, subsequent duplicate events return `200 OK` with `{ status: "ALREADY_TERMINAL", current_status }` without executing duplicate database mutations or sending redundant signals (D-14).

- Threat T-04-11: Unhandled promise rejections, hanging requests, or webhook failure cascades caused by temporary latency or unavailability of Trust Graph port 8001.
  - ASVS Control: V13.1.1 (Resilience and Fault Isolation).
  - Mitigation: Telemetry signal dispatch to `http://localhost:8001/trust/signal` is executed asynchronously in fire-and-forget mode with comprehensive `.catch()` error absorption (D-15, §6.4). Network drops, port 8001 timeouts, or rehydration delays on the Trust Graph do not fail or delay the 200 OK acknowledgment returned to Razorpay.
</threat_model>

<action>
1. Implement `src/lib/webhook-verifier.ts`:
   - Expose `timingSafeCompare(a: string, b: string): boolean`:
     - Convert strings to UTF-8 Buffers: `Buffer.from(a, 'utf8')`, `Buffer.from(b, 'utf8')`.
     - Check byte length equality: if `bufA.length !== bufB.length`, return `false` immediately.
     - Call `crypto.timingSafeEqual(bufA, bufB)` and return boolean (D-13).
   - Expose `verifyRazorpaySignature(rawBody: string, signature: string | null, secret: string): boolean`:
     - If signature is missing or empty, return `false`.
     - Compute expected signature: `crypto.createHmac('sha256', secret).update(rawBody, 'utf8').digest('hex')`.
     - Return `timingSafeCompare(signature, expectedSignature)`.
2. Implement `test/helpers/webhook-generator.ts`:
   - Implement `generateSignedWebhook(options: GenerateWebhookOptions)` matching §8.2:
     - Support events: `'payment.captured'`, `'payment.failed'`, `'order.paid'`, `'payment.authorized'`.
     - Parameters: `nexusTransactionId`, `merchantId`, `amountPaise`, `paymentId`, `orderId`, `secret`, `errorDescription`.
     - Construct standard Razorpay event payload with `notes: { nexus_transaction_id, merchant_id }`.
     - Serialize to `rawBody = JSON.stringify(payload)`.
     - Compute HMAC-SHA256 signature using `secret`.
     - Return `{ payload, rawBody, signature }`.
   - Implement helper `generateTamperedWebhook(options, tamperWith)` to generate mismatched signatures and modified body payloads for negative security tests.
</action>

<action>
1. Implement `src/app/api/webhooks/razorpay/route.ts`:
   - Handle `POST(req: NextRequest)`:
     - Extract `x-razorpay-signature` header. If missing, return `400 Bad Request` with `{ error: "Missing signature header" }`.
     - Read raw body text once using `await req.text()` (D-13, §6.2).
     - Verify signature using `verifyRazorpaySignature(rawBody, signature, secret)`. Secret comes from `process.env.RAZORPAY_WEBHOOK_SECRET || "whsec_nexus_test_secret"`.
     - If signature is invalid, return `400 Bad Request` with `{ error: "Invalid webhook signature" }`.
     - Parse `rawBody` as JSON.
     - Extract `event`, `payload.payment.entity`, and `payload.order.entity`.
     - Extract `nexus_transaction_id` from payment notes or order notes (`notes.nexus_transaction_id`).
     - If `nexus_transaction_id` is missing, return `200 OK` with `{ status: "IGNORED_NO_TRANSACTION_ID" }`.
     - Query PostgreSQL `transactions` table:
       `SELECT id, merchant_id, status, amount_paise, buyer_fingerprint, razorpay_payment_id FROM transactions WHERE id = $1`.
     - If transaction not found in database, return `404 Not Found` with `{ error: "Transaction not found" }`.
     - **Terminal State Idempotency Guard (D-14)**:
       If `txn.status === "SUCCESS" || txn.status === "FAILED"`, return `200 OK` with `{ status: "ALREADY_TERMINAL", current_status: txn.status }`. Do not update status or dispatch signals.
     - **Event Handling & Status Transition (RZP-04)**:
       - If `event === "payment.captured"` or `event === "order.paid"`:
         - Update transaction: `UPDATE transactions SET status = 'SUCCESS', razorpay_payment_id = $1, resolved_at = clock_timestamp() WHERE id = $2`.
         - Dispatch non-blocking signal to Trust Graph port 8001 via `dispatchTrustSignalNonBlocking` with outcome `'SUCCESS'` (D-15).
       - If `event === "payment.failed"`:
         - Update transaction: `UPDATE transactions SET status = 'FAILED', failure_reason = $1, resolved_at = clock_timestamp() WHERE id = $2`.
         - Dispatch non-blocking signal to Trust Graph port 8001 via `dispatchTrustSignalNonBlocking` with outcome `'FAILED'` (D-15).
     - Return `200 OK` with `{ status: "PROCESSED", event, new_status }`.
2. Implement `test/routes/webhook.test.ts`:
   - Use `generateSignedWebhook` helper from `test/helpers/webhook-generator.ts`.
   - Mock `@nexus/db` query calls.
   - Mock global `fetch` calls for Trust Graph port 8001.
   - Test suite:
     - 400 when `x-razorpay-signature` header is missing.
     - 400 when signature does not match expected HMAC.
     - Timing safety & length guard: verifies buffer length mismatch does not throw `RangeError` (ASVS V3.2.1).
     - 200 `IGNORED_NO_TRANSACTION_ID` when webhook payload lacks `nexus_transaction_id`.
     - 404 when `nexus_transaction_id` does not exist in DB.
     - 200 `PROCESSED`: `payment.captured` updates transaction to `SUCCESS` and records `razorpay_payment_id`.
     - 200 `PROCESSED`: `payment.failed` updates transaction to `FAILED` and records `failure_reason`.
     - 200 `ALREADY_TERMINAL`: idempotency guard ignores duplicate webhook events when transaction is already `SUCCESS` or `FAILED` (D-14).
     - Trust Graph feedback: verifies that valid status transitions trigger `POST /trust/signal` with correct payload without failing the webhook response even if port 8001 fails (D-15).
</action>
