<threat_model>
ASVS Level: 1
Block on: high severity threats

- Threat T-04-01: Authentication bypass or merchant impersonation via forged Bearer tokens or plaintext key leakage in query logs / URLs.
  - ASVS Control: V3.1.1 (Cryptographic Key Management), V5.1.1 (Input Validation - token formatting).
  - Mitigation: Gateway enforces Bearer token syntax `/^Bearer\s+(nx_live_[a-zA-Z0-9]{24,})$/i` or `maas_live_*`, hashes the token via SHA-256 (`hashMaasToken`), and checks `merchants.maas_token_hash`. If token is invalid/absent, returns 401 Unauthorized; if token belongs to another merchant, returns 403 Forbidden; if merchant does not exist, returns 404 Not Found (D-05, D-06).

- Threat T-04-02: Denial of Service (DoS) and vector search resource exhaustion via high-velocity scraping or expensive pgvector cosine distance operations.
  - ASVS Control: V13.1.1 (Denial of Service - rate limiting).
  - Mitigation: In-memory sliding-window rate limiter enforces 60 rpm for catalog search per merchant ID (D-07). Exceeding limits rejects requests with 429 Too Many Requests and `Retry-After: 60`. Query parameter `limit` is strictly clamped to `[1, 50]`. Old timestamp buckets are pruned automatically to prevent memory leaks.

- Threat T-04-03: SQL injection or prompt injection via search query string `q` and query parameters.
  - ASVS Control: V5.2.1 (Sanitization of search strings), V5.3.1 (Parameterized database queries).
  - Mitigation: All database queries use parameterized SQL (`query(sql, [vectorStr, merchantId, limit])`). Gemini embeddings are serialized strictly as float arrays `[0.123, -0.456, ...]` before casting to `$1::vector`. ILIKE search strings are treated as parameters (`$2`), never concatenated into raw SQL strings.
</threat_model>

   - Implement an in-memory sliding-window rate limiter keyed by `key: string` (e.g., `merchant:${merchantId}:${route}`):
     - Track array of request epoch millisecond timestamps `number[]` per key.
     - Prune timestamps older than `windowMs` (default 60,000 ms) on every call.
     - Method `checkRateLimit(key: string, limit: number, windowMs: number = 60000): { allowed: boolean; remaining: number; resetMs: number }`.
     - Return `allowed: false` and `resetMs` when count exceeds `limit` (60 for catalog, 20 for transact per D-07).
     - Provide automatic background cleanup interval (every 5 minutes) or threshold-based pruning to avoid memory leaks per §6.5.
     - Expose `resetRateLimits()` helper for test isolation.
2. Implement `src/lib/auth.ts`:
   - Implement `authenticateMaaSRequest(req: Request | NextRequest, expectedMerchantId: string)`:
     - Read `Authorization` header. If missing or does not match `Bearer <token>` pattern, return `{ authenticated: false, status: 401, error: "UNAUTHORIZED", message: "Missing or malformed Bearer token" }` (D-06).
     - Extract raw token string. Validate token structure: prefix `nx_live_` or `maas_live_`, length >= 24. If invalid, return 401.
     - Hash token using `hashMaasToken(token)` from `@nexus/db` (SHA-256 hex digest per D-05).
     - Query PostgreSQL: `SELECT id, name, is_active FROM merchants WHERE maas_token_hash = $1`.
     - If no merchant found, check if token hash exists for ANY merchant. If token is invalid across all merchants, return 401 Unauthorized.
     - If token matches a valid merchant but `merchant.id !== expectedMerchantId`, return `{ authenticated: false, status: 403, error: "FORBIDDEN", message: "Token does not belong to specified merchant" }` (D-06).
     - Check if `merchant.is_active === false`. If inactive, return 403 Forbidden.
     - Check if `expectedMerchantId` exists in `merchants` table. If merchant does not exist in DB at all, return `{ authenticated: false, status: 404, error: "NOT_FOUND", message: "Merchant not found" }` (D-06).
     - Return `{ authenticated: true, merchant: { id, name, is_active } }`.

     - 401 on malformed Authorization header (e.g. `Basic abc`, `Bearer short`).
     - 401 on unknown token hash.
     - 403 on token belonging to merchant B when querying merchant A (D-06).
     - 404 when target merchant does not exist in database (D-06).
     - 200 / authenticated: true when valid token matches target merchant.
     - 429 Too Many Requests when sliding window limit (60 for catalog, 20 for transact) is exceeded, verifying `Retry-After` header calculation (D-07).

   - Expose `generateEmbedding(text: string): Promise<number[] | null>`.
   - Check `process.env.GOOGLE_API_KEY` or `process.env.GEMINI_API_KEY`. If absent, log warning and return `null` (D-01).
   - Use `GoogleGenerativeAI` from `@google/generative-ai` with model `models/text-embedding-004`.
   - Call `model.embedContent(text)`. Validate that returned values array is 768 dimensions. If valid, return `values`; on error/catch, log warning and return `null` (D-01).
2. Implement `src/lib/url-helpers.ts`:
   - Expose `buildAgentPurchaseUrl(req: Request | NextRequest, merchantId: string): string`:
     - Inspect request headers `x-forwarded-proto`, `host`, fallback to `process.env.NEXT_PUBLIC_APP_URL` or `http://localhost:3000` (D-04).
     - Return `${baseUrl}/api/maas/${merchantId}/transact`.
   - Expose `formatPaiseToInr(amountPaise: number): string`:
     - Format integer paise to display string (e.g. `2999000` -> `₹29,990`) strictly for presentation per §6.1. Never use floats in database queries or price calculations.
3. Implement `src/app/api/maas/[merchant_id]/catalog/route.ts`:
   - Handle `GET(req: NextRequest, { params }: { params: { merchant_id: string } })`:
     - Rate limit check: key `merchant:${merchant_id}:catalog`, limit 60 rpm (D-07). On breach, return 429 with `Retry-After: 60`.
     - Extract query parameters: `q` (search query string), `category`, `max_price_paise` (integer paise), `in_stock` (boolean, default true), `limit` (clamped `1..50`, default 10).
     - Lookup merchant name from `merchants` table using `params.merchant_id`. If merchant not found, return 404.
     - **Path A: Semantic Vector Search** (if `q` is non-empty and `generateEmbedding(q)` yields 768d vector):
       - Serialize vector as `[v1,v2,...]`.
       - Execute SQL query with pgvector `<=>` cosine distance operator:
         `SELECT id, merchant_id, name, description, price_paise, currency, stock, category, tags, ROUND((1 - (embedding <=> $1::vector))::numeric, 4) AS match_score FROM products WHERE merchant_id = $2 AND is_active = true ... ORDER BY embedding <=> $1::vector ASC LIMIT $3` (using HNSW index `idx_products_embedding_hnsw`).
       - Apply 0.5 threshold: filter products with `match_score >= 0.5` (distance <= 0.5) (D-02).
       - If 0 products meet the 0.5 threshold, return the top 3 closest items with their lower scores so calling agents receive the nearest matches (D-02).
     - **Path B: Browse Mode / ILIKE Fallback** (if `q` is empty OR embedding returns null):
       - If `q` is absent: Browse mode returns all in-stock products ordered by `created_at DESC` with `match_score: 1.0` (D-03).
       - If `q` is present but embedding failed: Fall back to SQL `ILIKE` across `name ILIKE $param OR description ILIKE $param OR category ILIKE $param` with `match_score: 0.75` (D-01).
     - For each product in the result set, attach `price_display: formatPaiseToInr(p.price_paise)` and `agent_purchase_url: buildAgentPurchaseUrl(req, params.merchant_id)` (D-04, MAAS-02).
     - Return status 200 with JSON payload matching PRD §11.1: `{ merchant_id, merchant_name, query, result_count, products: [...] }`.
4. Create `test/routes/catalog.test.ts`:
   - Mock `@nexus/db` query responses and Gemini embedding client.
   - Test suite:
     - 404 when merchant does not exist in DB.
     - Browse mode on empty `q`: returns products with `match_score: 1.0` ordered by `created_at DESC` (D-03).
     - Semantic vector search: invokes embedding, passes vector to pgvector `<=>`, filters >= 0.5 match score (D-01, D-02).
     - Closest fallback: when all match scores < 0.5, returns top 3 closest products (D-02).
     - ILIKE fallback: when Gemini API throws or key is missing, queries products using SQL ILIKE with match_score 0.75 (D-01).
     - Correct paise currency representation (`price_paise: 2999000`, `currency: "INR"`, `price_display: "₹29,990"`) and dynamic `agent_purchase_url` pointing to transact endpoint (D-04, MAAS-02).
</action>
