# Quick Plan: Settings Tab cURL Commands & Store Unregistration / DB Wipe

## Description
In the merchant dashboard settings tab (`src/app/dashboard/settings/page.tsx`), provide:
1. Ready-to-use cURL commands for MaaS autonomous transactions and catalog querying, populated with active merchant ID, token, and sample store products.
2. A "Regenerate Token" capability so merchants can always obtain a fresh, working MaaS Bearer token without re-onboarding.
3. A "Danger Zone: Unregister & Delete Store" feature allowing merchants to permanently delete their store and all associated entities (audit entries, transactions, products, keys) from the database with confirmation.

## Tasks
1. Create `src/app/api/merchant/[id]/route.ts`:
   - `GET`: Return merchant profile, statistics (product, transaction, audit counts), and sample product.
   - `DELETE`: Atomic transactional cascade deletion with `SET LOCAL session_replication_role = 'replica'` to purge audit_entries, transactions, products, and merchant.
2. Create `src/app/api/merchant/[id]/token/route.ts`:
   - `POST`: Generate new MaaS token and update token hash/preview in DB.
3. Update `src/app/dashboard/settings/page.tsx`:
   - Display real merchant details & statistics.
   - Add MaaS API & cURL Command section with copy buttons and token regenerator.
   - Add Danger Zone with confirmation dialog to unregister & wipe store data from DB.
4. Verify end-to-end (cURL execution, deletion cascade, UI updates).
